# OpenCodeInfo — OpenCode Zen & Go Model Benchmarks & Cost

Static site + refresh script for OpenCode Zen model pricing, composite ranking, AA Coding Index, SWE-bench Pro, Bug Hunt, FrontierCode 2.0, Terminal-Bench 2, Terminal-Bench 4, and DeepSWE.

## Commands
- Serve the page:            `python3 -m http.server` → http://localhost:8000/docs/index.html
- Update data:               `python3 update_zen_prices.py --output docs/models.json`   (adds models, refreshes prices + rankings + SWE-bench Pro + Bug Hunt + FrontierCode 2.0 + Terminal-Bench 2/4 + DeepSWE; flags N.A., never removes)
- Prune stale N.A. models:   `python3 prune_na_models.py --output docs/models.json`     (removes models N.A. for over 6 months; `--dry-run` to preview)
- Preview changes:           `python3 update_zen_prices.py --dry-run --output docs/models.json`
- Prices only, no sync:      `python3 update_zen_prices.py --no-sync --output docs/models.json`
- Validate data file:        `python3 -m json.tool docs/models.json`

## Files
- `docs/index.html`          — the page (table, filters, sorting)
- `docs/models.json`         — data source (205 rows); the page fetches this
- `update_zen_prices.py`     — fetches catalogs/pricing, computes transitive rankings, and rewrites docs/models.json
- `prune_na_models.py`       — removes models N.A. for over 6 months (uses `naSince`)
- `readme.md`                — usage docs (README.md)
- `.github/workflows/update_models.yml` — daily job (03:00 UTC) that runs the update script + the N.A. prune and commits docs/models.json + docs/index.html

## models.json data model
Each entry: `name`, `rank` (composite benchmark rank 1–K calculated via log-odds latent skill with 2-parameter Mean-Sigma anchored equating and conservative Bayesian LCB weighting, `null` if unranked; may be a string like `"89?"` when every score behind it is identity-inferred — the page renders the `?` verbatim with a tooltip and sorts it numerically),
`params` (total parameters, e.g. "744B", "1.6T", `null` if undisclosed),
`context` (e.g. "1M", "500K"), `codingIndex` (AA Coding Index %, 0–100, `null` if unpublished),
`swePro` (SWE-bench Pro %, 0–100, `null` if unpublished; may be a string like `"9.67?"` when inherited from an unconfirmed identity),
`bugHunt` (Bug Hunt Bench, **planted bugs fixed out of 105** — a count, not a percentage — `null` if not evaluated),
`frontierCode2` (FrontierCode 2.0 mergeability %, 0–100, `null` if not evaluated),
`terminalBench2` (Terminal-Bench 2 %, 0–100, `null` if unpublished; 2.1 preferred, else 2.0),
`terminalBench4` (Terminal-Bench 4 %, 0–100, `null` if unpublished; 4.1/4.0/AA),
`deepSwe` (DeepSWE %, 0–100, `null` if unpublished),
`inputCost`/`outputCost`/`cachedReadCost` (USD per 1M tokens),
`plan` (`"go"` = Go $10/mo plan, `"zen"` = Zen pay-as-you-go row (a model Zen alone carries, or the Zen half of a per-plan split), `"openrouter"` = OpenRouter programming-category row with OpenRouter's own pricing/context, which can differ from its Zen/Go twins; the page badges rows (Zen)/(Go)/(Go · Zen)/(OpenRouter) after the model link), `alsoOnZen` (`true` when a Go-plan model is also on Zen pay-as-you-go **at the same price**, so one row covers both — a model the two plans price differently gets a separate `go` row and `zen` row instead, and neither carries this flag; omitted otherwise), `na` (`true` = N.A. — no longer selectable in OpenCode's model picker; only applied to zen/go rows; omitted otherwise), `naSince` (ISO date the model was first flagged N.A.; only present with `na`),
`hfUrl` (HF card, else BenchLM specs, else manufacturer; stealth models with no real model-info page use their `#...-note` anchor in the page's stealth-model notes, rendered as a same-tab link), `addedOn` (ISO date the model was added to the page; only present within its first month — the page badges it green "(New)" with the added date as tooltip).

## Update rules (update_zen_prices.py)
- Catalog = union of https://opencode.ai/zen/v1/models + .../zen/go/v1/models; `plan` reflects Go membership, `alsoOnZen` marks Go-plan models present in the Zen catalog at the same price (Go price wins for those). Models that leave the catalogs are NEVER removed from models.json — they stay listed and keep their last-known data, flagged `na: true` by the availability check.
- OpenRouter: `sync_openrouter` adds/updates rows for the Programming-category models listed in `OPENROUTER_DISPLAY` (64 ids: 45 of the 46 text models https://openrouter.ai/models?categories=programming listed on 2026-11-15 — all but `deepseek/deepseek-v4.1-flash` — the pre-1017 September build, excluded because `BENCH_SLUG_OVERRIDES`' undated alias would hand it the 1017 build's scores and `canonical_id` would merge it into the 1017 rank — plus 19 ids that have since dropped out of the category and keep their rows under the retention policy. The category's 2 "Decisions" models (Jev 1.13/1.14) are out of scope: typed-answer models with no catalog name match and nothing the benchmark columns measure. The UI computes the category client-side and virtualizes the list, so it cannot be read from the API (`?category=programming` returns a top-20 ranked slice, and `?categories=` is ignored) — re-sweeping means scrolling the page. All but `poolside/laguna-s-2.1:free` and `qwen/qwen3.8-max` are present in models.dev's `openrouter` provider, which is what the OpenCode model picker consumes) as `plan: "openrouter"`, named with the bare display name — OpenRouter pricing/context can differ from Zen/Go, so twins get separate rows distinguished by the page's (OpenRouter) badge (legacy "<Display> (OpenRouter)" names are renamed on sync). `reconcile` never touches openrouter rows (separate identity space). The script fetches the full catalog (https://openrouter.ai/api/v1/models) and syncs only mapped ids. `OPENROUTER_DISPLAY`/`OPENROUTER_PARAMS` map ids; params mirror the Zen/Go twins. `OPENROUTER_CODING_INDEX` holds AA Coding Index values from OpenRouter's benchmarks API (auth required, so curated snapshots; matched per model build — e.g. 0731↔20260731). OpenRouter rows are skipped by the N.A. pass but DO get BenchLM swePro/bugHunt/frontierCode2/terminalBench2/terminalBench4/deepSwe via `merge_benchmarks` (same underlying model). `cross_copy_benchmarks` then fills any benchmark field still missing on one twin from the other (both directions, incl. codingIndex; never overwrites existing values), so Zen/Go rows and their OpenRouter twins show identical benchmarks. Note: OpenRouter adds a 5.5% service charge on top of its listed prices — rows show listed prices, and the page header says so.
- Pricing from https://opencode.ai/docs/zen#pricing and https://opencode.ai/docs/go; Go price wins where both exist.
- Per-plan row split: a model in both catalogs that the two plans price differently gets TWO rows — `plan: "go"` at the Go price and `plan: "zen"` at the Zen pay-as-you-go price — instead of one `alsoOnZen` row that would show only the Go price (badged (Go) and (Zen) separately; currently DeepSeek V4.1 Flash 1017 at $0.15/$0.60 vs $0.30/$1.20 and DeepSeek V4 Pro at $0.66/$1.98 vs $1.74/$3.48). `split_plan_ids` reads the divergence from models.dev's per-provider `cost` (`opencode` vs `opencode-go`), NOT from the docs pricing tables: those list a model's context tiers as separate rows whose names normalize to one key (MiniMax M3 "≤ 512K"/"> 512K"), so a tier price can shadow the base rate and fake a divergence — base rates only, `tiers`/`context_over_200k` surcharges ignored. The split is sticky (once both rows exist they stay, so a row can never be stranded unpriced and unflagged if the prices later converge), each row keeps its own plan's price/`goUsage`, and `reconcile` matches a row to its own plan first so a model that merely changes plan is still updated in place rather than duplicated. A split sibling gets no `addedOn` (it is not a new model, so no green "(New)" badge). `split_row_ids` derives the same set from the rows for the availability pass.
- Context/cost fallback from https://models.dev/api.json; `CONTEXT_OVERRIDES`/`PARAM_OVERRIDES`/`KNOWN_URLS` maps hold verified values. A trailing `?` in params/context values (e.g. Big Pickle `357B?`) marks inferred/uncertain figures — the page renders it verbatim and sorts it as if the `?` were absent.
- AA Coding Index + SWE-bench Pro + Bug Hunt + FrontierCode 2.0 + Terminal-Bench 2 & 4 + DeepSWE from https://benchlm.ai/data/models.json (`benchmarks.coding.aaCodingIndex` [Zen/Go rows] / `.swePro` / `["bug-hunt-bench"]` (planted bugs fixed, out of 105) / `.frontierCode2` (Cognition's mergeability score, mirroring https://cognition.com/frontiercode; Artificial Analysis' independent FrontierCode-AA 2.0 run is not used as a fill source because it diverges materially from the official board) / `.terminalBench21`+`.terminalBench2` (falling back to `agentic.aaTerminalBench21`, whose independent run tracks the official board within a point; Vals' 2.1 mirror runs ~11 points lower and is not used) / `coding.terminalBench41`+`agentic.terminalBench41`/`terminalBench4`/`aaTerminalBench4` / `.deepSwe`); `BENCH_SLUG_OVERRIDES` maps display names to BenchLM slugs; `BENCH_SLUG_OVERRIDES_RELEASED` points the score fields (swePro/FrontierCode/Terminal-Bench/DeepSWE) at a different build's slug for rows whose AA Coding Index was measured on a preview snapshot (Qwen3.8 Max ← `qwen3-8-max-preview` for the index, `qwen3-8-max` for the rest). `SWE_PRO_OVERRIDES` hardcodes Scale SWE-bench Pro scores BenchLM lacks (e.g. Claude Haiku 4.5 39.45, from labs.scale.com/leaderboard/swe_bench_pro_public). `BUG_HUNT_FALLBACKS` fills `bugHunt` from the publisher's own board (https://bughunt.productcompass.pm/data/benchmark.json, best non-superseded configuration per model) only where BenchLM has no value, so a future BenchLM import wins automatically; Free/Contributor variants inherit their base model's fallback. `BENCH_VALUE_OVERRIDES` hardcodes other fields BenchLM lacks or suppresses flawed runs (`{name: {field: score}}`, e.g. Flint 40B Free terminalBench2 54.9, vendor-reported; Beam Free terminalBench4 None to exclude Artificial Analysis's flawed 3.0% run). `BENCH_INHERIT_FROM` copies a free variant's benchmarks from its non-free counterpart (e.g. Ox Alpha Free ← GLM-5.3-Flash, incl. codingIndex from `.aaCodingIndex`), and fills fields BenchLM lacks from the counterpart's own row (never overwriting). Free variants with no paid twin row map straight to the base model's BenchLM slug in `BENCH_SLUG_OVERRIDES`. Discounted pricing cells (`<del>$old</del> $new`) use the current price. A model listed once per pricing variant collapses to one row, so `extract_pricing_table` keeps only its headline rate: the `(Off-Peak)` row over `(Peak)`, and the base context tier over the surcharge above it (`TIER_SURCHARGE` skips `(> 512K tokens)`, `(over 200K)`, `(≥ 1M)` and the like — before it, any threshold not starting with "2" slipped through and overwrote the base rate, which is why MiniMax M3 showed its > 512K price and Claude Haiku 5.5 its > 100K price). `UNCERTAIN_BENCH_OVERRIDES` stores identity-inferred scores verbatim with a trailing `?` (Big Pickle swePro `9.67?` = GLM-4.6's Scale score, terminalBench2 `49.4?` = GLM-4.6's AA Terminal-Bench v2.1 run) — benchmark fields may carry `?`, which the page renders verbatim and filters/sorts numerically; a real published score replaces them (comparisons are numeric).
- Ranking: `compute_model_ranks` computes a global composite ranking across all benchmark suites via log-odds latent skill (IRT logistic link) with 2-parameter Mean-Sigma anchored equating and conservative Bayesian lower-confidence-bound (LCB) weighting ($\lambda_{\text{prior}} = 0.35$, $\kappa_{\text{LCB}} = 0.75$). Free/Contributor/OpenRouter twins, dated OpenRouter builds (a trailing `\s\d{4}`, e.g. `DeepSeek V4 Pro 0813` → `DeepSeek V4 Pro`, since OpenRouter lists dated builds of a model already present under its bare name) and `BENCH_INHERIT_FROM` aliases are deduplicated into canonical model identities (and unconfirmed `?` scores are excluded during calibration, with a confirmed value always winning over an uncertain one for the same canonical field) so duplicates and uncertain proxies cannot skew suite statistics or create rank gaps. Percentage scores are mapped to log-odds $\ell = \ln(p / (100 - p))$ to eliminate ceiling compression, then equated in both location ($b_f$) and scale ($a_f$) across multi-suite bridge models. Suite weights reflect recency and rigor (Terminal-Bench 4: 1.5×, DeepSWE: 1.5×, SWE-bench Pro: 1.0×, AA Coding Index: 1.0×, Bug Hunt: 1.0×, FrontierCode 2.0: 0.5×, Terminal-Bench 2: 0.5×); Bug Hunt's count is converted to a percentage ($p = \text{fixed} / 105 \times 100$) before the logit; conservative LCB ($R_m = \mu_m - \kappa \sigma_m$) penalizes sparse evaluations across the entire table without pulling weak single-suite models upward toward the mean (the penalty tracks suite coverage, not a model's dispersion across suites). Calibration guards: $a_f$ is bounded to $[0.4, 4.0]$ (observed range 0.56–1.90), a suite needs 3 bridge models before its scale is re-fit (a 2-point Mean-Sigma fit is exactly determined and unstable), and a suite with fewer than 2 confirmed values takes its moments from every score on that suite instead of an unequated raw log-odds scale. Standard competition ranking assigns integer ranks (1..K) to canonical models (scoring build-divergent OpenRouter rows on their own profile, clamped to 1..K); unranked models receive `null`, and a rank resting only on `?` scores is itself suffixed `?`.
- Model links: `hfUrl` comes from `KNOWN_URLS` (keyed by catalog id): the Hugging Face card when weights are open, else BenchLM model specs, else the manufacturer page. Revealed stealth codenames point at the model they turned out to be (Cat Jam → Beam, Crouton Alpha → Muse Ember, Fledge Alpha → Inkling 2 Small, LL Alpha → Flint, Space Bunny → MiniMax M3.1 Flash); still-anonymous/retired ones point at the stealth-model tracker (https://artificialwatch.com/stealth-models). `reconcile` maintains links for catalog rows, and `backfill_known_urls` fills them for rows the catalogs no longer list (N.A. rows); existing links are never overwritten. The page renders `#anchor` values as same-tab stealth-note links and everything else as a new-tab link.
- Availability: models.dev is the catalog OpenCode's model picker consumes; `na: true` when a model has no non-`deprecated` entry in either its `opencode` (Zen) or `opencode-go` (Go plan) provider. Split (per-plan) rows are checked against only their own plan's catalog and provider, so a model that leaves Zen but stays on the Go plan flags just its Zen row. Rows whose display name carries a build label the catalog id lacks ("DeepSeek V4.1 Flash 1017" → `deepseek-v4.1-flash`) resolve through `NAME_TO_ID`/`catalog_id_for`, which keeps the rename from flagging them N.A. `naSince` is set on first flag (backfilled on the first run for pre-existing flags) and cleared when the model becomes available again.
- Pruning: prune_na_models.py removes rows whose `naSince` is older than 6 months (`--months` to override); rows with missing/bad `naSince` are never removed. The daily workflow runs it after the update.
- New models: `reconcile`/`sync_openrouter` stamp new rows with `addedOn` (ISO date); the page shows a green "(New)" badge (tooltip = added date, e.g. "Added Sep 2, 2026") while under one calendar month old. Each run drops `addedOn` flags a month or older (`prune_new_flags`); existing rows never gain the badge retroactively.
- Every run refreshes the "Checked <date>." footer note in docs/index.html (`update_checked_date`); dry-run never writes.
- Do NOT hand-edit models.json — run the script.
- Always dry-run before writing (`--dry-run`), then validate the result, using the commands above.

## Web page (docs/index.html)
- Columns: Rank, Model, Params, Context, AA Coding Index, SWE-bench Pro, Bug Hunt, FrontierCode 2.0, Terminal-Bench 2, Terminal-Bench 4, DeepSWE, Output ($/1M).
- Default view: sorted by Rank (ascending); AA Coding Index, SWE-bench Pro, Terminal-Bench 2, Input ($/1M), Cached Read ($/1M), and Go Limits ($) are hidden by default (`defaultVisible: false` in `COLUMNS`) and enabled via choose columns.
- Narrow screens (≤760px): each row renders as a card whose header is the rank + model name + platform badge (rank sits left of the name, in the real Rank column's cell); tapping the header (or its ▸ chevron) expands the visible benchmark/cost rows. Expansion state is kept across re-renders (`expandedCards`), and header links still navigate.
- Filters: Plan (All Models / New Models = added within the last month, same window as the green (New) badge / Zen Models = on Zen pay-as-you-go, incl. Go-plan models marked `alsoOnZen` (a split model's Zen row matches here and its Go row does not) / Go Plan Models / OpenRouter Models / Free Models = $0 input and output price) + "Available only" checkbox (hides `na` models), Min AA index, Min SWE-bench Pro, Min Bug Hunt (0–105), Min FrontierCode 2.0, Min Terminal-Bench 2, Min Terminal-Bench 4, Min DeepSWE, Max output ($/1M) — same order as the columns; Reset clears all.
- Click the sort button (⇅) or column header to sort; `null` scores/params sort last and render as "—". Selecting a new sort column keeps the previous sort as the secondary (tiebreaker) sort; Reset clears it. Benchmark header names link to the originator's page.
